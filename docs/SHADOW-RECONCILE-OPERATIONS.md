# Default-off event-driven inventory (#5, #6, #10)

This is an intermediate read-only self-pilot listener. Its inventory responds to issue changes, target-branch PR changes, selected CI completions (Factory validation and Windows Aspire runtime), protected main pushes, and manual requests. Completion events are wake-up hints only; the inventory does not use their payload, artifacts or status as authority. Manual dispatch is restricted to refs/heads/main; the job refuses other branch or tag refs. The inventory uses a trusted main checkout and bounded public issue and PR reads. Git credentials are never persisted. The listener reports incomplete evidence and has no dispatch or merge operations. Review-completion coverage, trusted policy retrieval, complete evidence normalization, durable event deduplication and loss/restart recovery remain open. The proposed ten-minute recovery schedule runs at UTC minutes 3,13,23,33,43,53 using the same read-only, opt-in inventory. GitHub scheduling is best effort; it may delay or skip a tick. A scheduled inventory is not full reconciliation or agent dispatch. Demonstrate actual cadence and missed-event recovery before claiming heartbeat acceptance.

Inventory is default-off unless the repository variable FACTORY_SHADOW_ENABLED is exactly lowercase true. The job-level `if` expression checks `github.repository`, `github.repository_id == '1471342715'`, `github.ref == 'refs/heads/main'`, `github.ref_protected == true`, `vars.FACTORY_SHADOW_ENABLED == 'true'`, and same-repository `workflow_run` head identity before allocating a runner; `concurrency` is scoped to the `inventory` job so skipped default-off runs never contend on the concurrency lock. Because GitHub expression comparisons are case-insensitive, a case-sensitive Bash check before checkout (`GITHUB_REPOSITORY=Jamula/SoftwareFactory`, `GITHUB_REPOSITORY_ID=1471342715`, `GITHUB_REF=refs/heads/main`, `GITHUB_REF_PROTECTED=true`, `FACTORY_SHADOW_ENABLED=true`) gates all remaining steps. Activation requires independent security review, confirmation of main protection and included capacity, and separately verified owner authorization. Disable by removing or setting the variable false; cancel any already-running read-only job if required. GitHub concurrency serializes active jobs; cross-run durable lease storage (#6) remains separate from runner-local SQLite. Do not claim an unattended issue-to-merge cycle or two-minute target from this workflow.

Before enablement verify the current workflow revision and its permissions, runner availability, read-only network behavior and actual event coverage. Demonstrate live inventory with zero mutation, capture actual event-to-inventory latency and failures, then proceed to trusted review/check normalization and a separately authorized protected integration path. Never add PR-controlled checkout, artifacts, commands, secrets or privileged token permissions to this workflow.

The PR identity path requires both `FACTORY_SHADOW_ENABLED=true` and `FACTORY_PULL_EVENT_SHADOW_ENABLED=true` as case-sensitive opt-ins. It runs only on `pull_request_target`, checks out the immutable workflow commit from protected `main`, and passes the event's PR number and head SHA as environment values. The adapter checks the workflow identity, checkout SHA and repository ID before reading only that PR with an unauthenticated GitHub GET. It rejects fork PRs, moved heads, mismatched identities, missing data, stale reads and ambiguous rate or permission errors. Its output contains identifiers, state, draft status and elapsed adapter time. Event-to-decision timing needs a separate delivery timestamp. Reconciliation returns incomplete shadow evidence and provides no review, check or merge authorization. The workflow leaves both opt-ins under owner control.


Issue and manual reconciliation are separately gated by `FACTORY_ISSUE_EVENT_SHADOW_ENABLED=true` in addition to the global opt-in. The issue listener covers issue metadata changes and runs the trusted `workflow_sha` checkout, then performs a bounded unauthenticated public read of issue number, repository, and state only. It discards title and body. Manual `workflow_dispatch` reconciliation is available on protected `main` when an issue number is supplied. Both paths require repository ID, protected main ref, workflow ref and SHA agreement, fresh issue identity, and a valid run ID. Results remain incomplete shadow evidence; there is no event ledger, durable deduplication, review/check normalization, authorization, dispatch, or merge. Leave the variable unset until separately reviewed and authorized.

The pre-checkout Bash guard requires case-sensitive `GITHUB_REPOSITORY=Jamula/SoftwareFactory`, `GITHUB_REPOSITORY_ID=1471342715`, `GITHUB_REF=refs/heads/main` and `GITHUB_REF_PROTECTED=true` for every execution path. Case-insensitive GitHub expressions are only a coarse filter. Case variants, mismatched repository IDs, or unprotected refs cannot enable any checkout or inventory execution.

## Completed check (`workflow_run`), protected `main` (`push`), and review trigger adapters (#5)

In addition to `pull_request_target` and `issues`/`workflow_dispatch`, `tools/engineering-factory/event-envelope.mjs` provides metadata-only adapters and trigger reconcilers parameterized via `resolveTrustedScope` (`repository`, `repositoryId`, `branch`, `workflowPath`; defaulting to `Jamula/SoftwareFactory`, `1471342715`, `main`, and `.github/workflows/shadow-reconcile.yml`):
- **Check (`workflow_run`) reconciliation** (`readCheckRunIdentity`, `reconcileCheckTrigger`): gated in `.github/workflows/shadow-reconcile.yml` by `FACTORY_CHECK_EVENT_SHADOW_ENABLED=true` on `workflow_run` (`completed`). Verifies immutable `workflow_sha` checkout on protected `main`, performs an unauthenticated bounded GET of `/repos/{owner}/{repo}/actions/runs/{run_id}`, rejects fork `head_repository` runs or non-completed states, discards `display_title` and commit text, and reconciles through `reconcileEventTrigger` / `event-journal.mjs`.
- **Protected `main` (`push`) reconciliation** (`readMainIdentity`, `reconcileMainTrigger`): gated in `.github/workflows/shadow-reconcile.yml` by `FACTORY_MAIN_EVENT_SHADOW_ENABLED=true` on `push` to `main`. Verifies numeric `repository.id` (`fork: false`) and `/branches/{branch}` (`protected: true`, `commit.sha`) before recording a shadow reconciliation or superseded-head receipt (`subject: 0`).
- **Review reconciliation** (`readReviewIdentity`, `reconcileReviewTrigger`): binds a trusted review hint to a fresh same-repository pull read before and after the review GET, discarding review body text and rejecting forked PRs, `PENDING` reviews, mid-read pull state changes (`PULL_STATE_CHANGED`), or moved heads (`HEAD_CHANGED`). Recovery without the exact triggering `reviewId` supersedes moved heads (`SHADOW_HEAD_SUPERSEDED`) and leaves unchanged-head claims unacknowledged (`EVIDENCE_UNKNOWN`) rather than matching unrelated reviews. Not wired as a direct `pull_request_review` workflow trigger so untrusted PR refs never execute workflow definitions.
- **Journal-backed orchestration** (`createScopedJournalReader`, `reconcileEventTrigger`): enqueues and reconciles normalized `pull`, `issue`, `manual`, `review`, `check`, and `main` triggers through `event-journal.mjs` with a default bounded 1-hour (`3600000` ms) retry deferral on unknown evidence so unacknowledged claims never starve later deliveries, supporting deterministic cross-run snapshot import/export (`importJournalSnapshot` / `exportJournalSnapshot`) while keeping `liveDispatch: false` and `liveMerge: false`.
- **Local diagnostic harness (`local-shadow-host.mjs`)**: explicitly marked `LOCAL_DIAGNOSTIC_ONLY = true` and guarded to refuse hosted or operational invocation (`LOCAL_DIAGNOSTIC_ONLY`). Under Roadmap v2, GitHub is the orchestrator and local workstation polling is never an operational host or lease store.


## Bounded review/check metadata adapter (#5)

The standalone `readPullSignals` adapter reads the same-repository pull identity before and after fetching one bounded review page and one bounded check-run page. It rejects forked or moved heads, a pull identity that changes during collection, pagination beyond the bounded page, malformed/duplicate records, rate or permission errors, and cross-head evidence. It requires complete UTC timestamps with calendar-valid dates, accepts GitHub's supported bot login suffix, and normalizes pending reviews and all documented nonterminal check states without treating them as approval or success.

It returns reviewer identity/state/head/timestamp and check app/name/status/conclusion/completion time only; review bodies, check output and annotations are discarded. The snapshot remains `evidenceComplete:false`, `liveDispatch:false`, and `liveMerge:false`; it does not establish the trusted event, policy decision, successful review, or queue eligibility. It is a reusable read-only adapter and is not yet wired to a trusted review/check event trigger. It performs four unauthenticated GitHub API reads; rate limits fail closed. A head change after the final read cannot be ruled out by a snapshot, so it remains non-authorizing. Do not enable it as an event listener until the trusted ingress, loss recovery, latency measurement, and any necessary least-privilege read path have independent review and owner authorization.
