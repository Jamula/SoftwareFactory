## Working protocol (effective for safe direct work; automation implementation remains gated)

1. Read main and PR heads, active lanes, all review summaries and inline threads, checks and dependencies together; identify critical path and assign non-overlapping ownership. Do not equate logical lanes with live agents.
2. Batch known defects and negative tests in one candidate. In a verified isolated local worktree use the pinned runtime, locked restore, targeted tests then full coverage; check the candidate diff and `git diff --check`. A clean local result is advisory, not trusted CI or independent review.
3. Push one atomic candidate per lane with expected-head protection. Run required Linux/Windows, security and independent final-head review concurrently. While external validation is pending, start other independent approved work rather than repeatedly polling the same PR.
4. Treat summary-only findings as material until independently dispositioned. A successful review job, COMMENTED state or zero inline threads is not by itself approval. Resolve only substantiated findings; any new head invalidates prior review evidence.
5. Integrate in protected dependency order; verify main; count only accepted outcomes, not PR count. Report new blockers once. Do not bypass checks to meet speed objectives.

No guaranteed speed multiplier. Stop any experiment that introduces missed findings, coverage regression, failed main, duplicate work, unauthorized mutations or unknown/increased cost. Later milestone features remain dependency-gated; no live provider dispatch, production deployment, credential changes, new paid services or review/protection relaxation.

## Multi-repository portfolio capacity allocation and train isolation (`#16`)

`tools/engineering-factory/portfolio-train-benchmark.mjs` (`allocatePortfolioCapacityAndSimulateTrains`) enforces deterministic, metadata-only portfolio scheduling and per-repository merge-train simulation across explicitly enrolled repositories:

1. **Verified quota and credential isolation:** Requires verified included-only capacity and a present, non-stale enforceable `$0`-overage hard-stop receipt (`budgetDecision` + mandatory `verifyHardStopReceipt`, `HARD_STOP_UNVERIFIED` when omitted), explicit owner enrollment (`enrolled: true`, `ownerAuthorized: true`), immutable identity binding (`Jamula/SoftwareFactory` $\leftrightarrow$ `1471342715`), unique per-repository `repo-read-only-shadow` credentials, and **zero shared admin tokens** (`sharedAdminToken: false`).
2. **SoftwareFactory first-claim priority without consumer preemption:** `Jamula/SoftwareFactory` (`1471342715`) receives strict first-claim priority on available shadow worker slots **without cancelling or preempting active in-flight consumer leases** (`cancelledInFlightLeases: 0`). Remaining capacity is distributed across healthy enrolled consumers by critical-path rank with fair round-robin tie-breaking under strict per-repository concurrency caps (for example, `Spellbook <= 2`, `FamilyTree <= 1`), deferring overlapping file-path claims (`PATH_OVERLAP_DEFERRED`).
3. **Logical lanes vs. worker authorization:** `20–50` portfolio logical lanes (and `12 / 50 / 100` benchmark tiers) are explicitly classified as `logical-lanes-not-concurrent-agent-authorization` (`authorizedConcurrentWorkers: 0`), never live concurrent agent authorization.
4. **Per-repository `main`-failure and kill-switch isolation:** Each enrolled repository simulates its own serialized integration train (`rebasesPerformed: 0` on prevalidated non-conflicting candidates, verified merge-queue support/cost, exact-head/compatible-base checks, and repo-specific review/coverage floors such as `98%/95%` for `SoftwareFactory` and `97%/90%` for `Spellbook`), recording queue size, `p50`/`p95`, blocked time, last merge receipt, and verified-`main` drain against the `120 s` stretch target (`stretchTargetOnly: true`). A tripped `killSwitch`, unhealthy initial `main`, or post-merge `main` failure halts **only** that repository's train and dependent dispatches (`crossRepoMainFailureSpillover: false`), leaving peer repositories unaffected.

## Language, `.NET 10` MAF consolidation, and hosting experiment boundary

Per owner decisions (2026-11-26 PT, `#118` / `#16` / `#142`), earlier optional Rust adoption—including `#118`'s Python dashboard-tooling replacement, which targets pinned Node.js `26.13.1` so M01 avoids adding an uncached `cargo` + `llvm-cov` CI toolchain on Linux and Windows runners—is superseded in M02.04 (`#16`) by the **single-runtime `.NET 10` + Microsoft Agent Framework (`1.28.0+` GA)** consolidation benchmark (`evaluateDotnetConsolidationBenchmark` in `tools/engineering-factory/portfolio-train-benchmark.mjs`; historical `evaluateEngineExperiment` remains covered for replay compatibility).

1. **Node-first authoritative baseline:** Profile pinned Node.js (`26.13.1`) first on GitHub-hosted Linux and Windows runners across `12`, `50`, and `100` simulated **logical lanes** (explicitly labeled `logical-lanes-not-concurrent-agent-authorization`; any `concurrentAgentAuthorization: true` claim fails closed with `UNAUTHORIZED_CONCURRENT_AGENT_CLAIM`). Keep the pure Node evaluator authoritative (`retain-node-authoritative`) until consolidation gates pass.
2. **`.NET 10` MAF (`1.28.0+` GA) architecture and CI-inclusive comparison:** Compare Node `26.13.1` against `.NET 10` (`10.0.404`) + `Microsoft.Agents.AI.Workflows` (`1.28.0+` GA) on matched GitHub-hosted Linux and Windows workloads across `12`, `50`, and `100` simulated logical lanes with equal `configuredWorkerCap` (`<= 12`) on every paired tier (`UNMATCHED_WORKER_CAP` otherwise), requiring:
   - Deterministic Pregel superstep execution, `CheckpointManager.CreateJson` (`ICheckpointStore<JsonElement>`) cross-process resumption with `priorSuperstepsRepeatedOnResume === 0`, native Aspire 17 `ActivitySource` OpenTelemetry, offline shadow client enforcement, and zero legacy/excluded packages (`SemanticKernel`, `AutoGen`, `GitHubModels`, `Temporal`, `LangGraph`).
   - End-to-end latency explicitly inclusive of CI `dotnet restore` / `npm ci` (`ciRestoreMs`), `dotnet build` (`ciCompileMs`), and `98%` line / `95%` branch Coverlet/Node coverage (`ciCoverageMs`), alongside CPU time, peak memory, `p95` latency, contention wait, and cancellation propagation.
3. **Single-runtime consolidation threshold:** Recommend `dotnet-10-consolidation-eligible` (otherwise `retain-node-authoritative`) **only** when material net end-to-end improvement (`>= minNetGainPercent`, minimum `15%`) is proven across all `12`, `50`, and `100` logical-lane tiers and overall, paired with **verified hosted** matched cohorts (`2x` / `5x` / `10x` / `15x` / `20x` / `25x`, `>= 5` comparable accepted units, `>= 2x` achieved; `25x` stretch stays open until verified hosted `25x` outcomes), `>= 98%` line / `>= 95%` branch coverage with zero regression, zero rework/intervention/safety regressions, independent and security review, rollback readiness, and verified `$0` incremental spend. Runtime consolidation is never an M01 gate.

Full CI p50 <75 s is candidate event to last required check; also record first-job-start latency, queue and p95. Do not infer whole-pipeline speed from one job.
