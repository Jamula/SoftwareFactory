# Reporting accepted outcomes and velocity scorecards

The offline functions in `tools/engineering-factory/outcome-measurement.mjs` (`measureIssueOutcome`, `measureAcceptedCohort`, `buildVelocityScorecard`, `compareVelocityScorecards`) and `tools/engineering-factory/stage-aggregate.mjs` (`aggregateStage`, `compareStageWindows`, `aggregateGithubTiming`, `aggregateScorecardStages`) provide the reproducible read-only scorecard and aggregation contract for #18 (M02.02) and #9. [Historical GitHub proxies](HISTORICAL-GITHUB-PROXIES.md) remain strictly quarantined from autonomous outcome claims.

## Cohort outcome verification (`measureAcceptedCohort`)

Use `measureAcceptedCohort(entries, query, authorizedRepositoryIds)` with an authorized repository allowlist (`1..32` positive repository IDs). Each query identifies a single `repositoryId`, configured comparable `cohort` label, and `source` (`verified` or `synthetic`). Callers establish the cohort definition, exact evidence provenance, and `complete` inventory coverage. A cohort label identifies a configured class of comparable work and carries no issue, repository, or person names.

The query uses `fromMs` and `toMs` for a half-open acceptance window. Set `observedMs` to the trusted acquisition time (`observedMs >= toMs`) and supply `nowMs` and a positive `maxAgeMs` to fail closed on stale snapshots. Each entry has `cohort`, `source`, `issue`, `pulls`, and `cost`. Keep issue and pull records to the fields required by `measureIssueOutcome`. Use exact main verification for the merge commits of every explicitly required pull request. A report accepts at most 500 issue entries, 250 pull rows per issue, and 10,000 pull rows across the query.

For a closed issue, `measureIssueOutcome` checks explicit acceptance, readiness, and reopen timestamps along with required PR links and exact merge-SHA main verification. For an open issue, use a verified readiness timestamp and `null` acceptance. Missing or contradictory evidence counts as `unknown`. An item ready before `toMs` that remains open or accepts at/after `toMs` is right-censored (`censored`). Duplicate issue numbers, receipt reuse across verified outcomes, or safe-integer spend overflow fail closed.

Use `null` cost when no verified attribution exists. A measured cost receipt requires `repositoryId`, `issueNumber`, sanitized `receiptId`, `verified: true`, `currency: 'USD'`, non-negative integer `amountMicros`, and `observedMs` in `[acceptedAt, query.observedMs]`. A verified `$0` receipt (`amountMicros: 0`) is measured zero; an absent or unverified receipt is `unknown` (`null`), never zero.

## Speed and efficiency scorecard (`buildVelocityScorecard`)

Call `buildVelocityScorecard(input, authorizedRepositoryIds)` with exact keys `{ query, units, stageSamples, quality, historicalProxies, baseline }`:

1. **`query`**: `{ repositoryId, cohort, provenance, complete, stageSourceComplete, fromMs, toMs, observedMs, nowMs, maxAgeMs, coveragePolicy }`, where `provenance` is `'verified-autonomous-outcome'` or `'synthetic-fixture'`, and `coveragePolicy` is `{ profile: 'software-factory' | 'consumer', minLinePercent, minBranchPercent, expectedComponents }` (enforcing the `98%` / `95%` floor for `'software-factory'` and `95%` / `90%` floor plus stricter overrides for `'consumer'`, along with a complete expected component inventory). Supplying `'historical-github-proxy'` or mixing provenances across `query`, `units`, `stageSamples`, `cost`, `quality`, or `baseline` fails closed with `reason: 'PROVENANCE_ISOLATION_VIOLATION'`.
2. **`units`**: up to 500 sanitized issue-unit records `{ cohort, provenance, issue, pulls, cost, rework, utilization, humanInterventions }`. Extra fields (such as titles, prompts, bodies, or actor names), proxies, and property getters are rejected without invoking accessors:
   - `rework`: `null` or `{ complete, candidateRounds, reworkRounds, reopenedCount, infrastructureRetries, queueRevalidations }` (`reworkRounds === candidateRounds - 1`, and `(issue.lastReopenedAt !== null) === (reopenedCount > 0)`).
   - `utilization`: `null` or `{ complete, activeMs, blockedMs, idleMs, blockedReasons }`, where `blockedReasons` sums to `blockedMs` over `ALLOWED_BLOCKED_REASONS`. When `allocatedMs === 0`, ratios remain `null` (`reason: 'ZERO_ALLOCATED_CAPACITY'`).
   - `humanInterventions`: `null` or `{ complete, routineCount, governanceCount }`. Incomplete or `null` tracking sets `status: 'unknown'` and `zeroRoutineVerified: false` (never `0`).
   - `cost`: distinguishes `status: 'verified-zero'` (`$0` verified across all accepted units), `'verified-spend'`, and `'unknown'` (`null` totals/ratios whenever `accepted === 0`, `complete === false`, or any accepted unit lacks a verified receipt).
3. **`stageSamples`**: evaluated by `aggregateScorecardStages(samples, stageQuery, authorizedRepositoryIds)` across all seven canonical M02.02 stages (`ready->firstPr`, `draft->publish`, `publish->merge`, `creation->merge`, `merge->verifiedMain`, `eligible->merge`, `ciEvent->lastRequiredCheck`). Requires primitive string `stage` keys before lookup and reports nearest-rank `p50Ms`/`p95Ms` on completed in-window samples, `counts` (`cohort`, `completed`, `censored`, `unknown`), initial/stretch SLO miss counts, and `overdueOpenCount` for open items whose elapsed age at `observedMs` exceeds the initial target.
4. **`quality`**: `null` or `{ repositoryId, provenance, complete, head, components, failedMainCount, unauthorizedWriteCount, duplicateDispatchCount, budgetViolationCount }`. Requires every component in `query.coveragePolicy.expectedComponents` to match `quality.head` and individually satisfy `minLinePercent`/`minBranchPercent` in addition to summed overall counts and zero safety/budget violations.
5. **`historicalProxies`**: `null` or `{ provenance: 'historical-github-proxy', sourceComplete, issueCreatedToCloseRows, prCreatedToMergeRows }`. Output is isolated under `historicalProxyContext` (`nonAutonomousProxyOnly: true`) and never alters any autonomous velocity, cost, utilization, quality, or comparison field.
6. **`baseline` & sample-size gate (`compareVelocityScorecards`)**: requires `MIN_COMPARABLE_ACCEPTED_UNITS = 5` accepted units in both non-overlapping equal-duration windows of the same `repositoryId`, `cohort`, and `provenance`, positive throughput in both cohorts, verified non-regressing cost per accepted unit, `quality.status === 'passed'` with matching coverage policy thresholds and non-decreasing line and branch coverage counts, and measured rework and human interventions in both cohorts with no increase in absolute or per-accepted rework (including reopenings) or interventions (including governance) before reporting `throughputMultiplier` or `THROUGHPUT_CHECKPOINTS` (`[2, 5, 10, 15, 20, 25]`). `autonomousSpeedClaimEligible` is `true` only when `provenance === 'verified-autonomous-outcome'`, `known === true`, `accepted >= 5`, rework and utilization are measured, `zeroRoutineVerified === true`, `cost.status === 'verified-zero'`, and `quality.status === 'passed'`.

## Customer One usability, onboarding overhead, and portfolio view (`evaluateCustomerOneUsabilityAndPortfolio`)

`evaluateCustomerOneUsabilityAndPortfolio(input)` in `tools/engineering-factory/customer-one-usability-scorecard.mjs` evaluates #18's Customer One onboarding/usability overhead and multi-repository authorized portfolio view without introducing a hosted service or collector:

1. **Strict input validation & repository isolation**: requires plain objects with own enumerable data descriptors and dense `Array.prototype` arrays (rejecting ES `Proxy` instances, property getters/setters without invoking them, non-enumerable or symbol keys, and extra fields such as prompts, titles, actor names, or credentials). Every observation and optional `filters.repositoryIds` entry must belong to `authorizedRepositoryIds` (`1..32` distinct positive repository IDs); unauthorized repository IDs fail closed with `reason: 'UNAUTHORIZED_REPOSITORY'`. `perRepository` reports each authorized repository independently so peer consumer regressions or missing data never contaminate another repository.
2. **Evidence-class quarantine (`evidenceClass`)**: enforces strict separation across `'synthetic'`, `'historical-proxy'`, and `'verified-live'`. Mixing observations, metric shapes (`metrics` vs `proxyMetrics`), or `baseline` snapshots across evidence classes fails closed with `reason: 'EVIDENCE_CLASS_MIXING_FORBIDDEN'`. `'synthetic'` evaluations set `provisionalTargetsOnly: true` and `liveClaimEligible: false`; `'historical-proxy'` evaluations quarantine `issueCreatedToCloseMs` and `prCreatedToMergeMs` under `historicalProxySummary` (`nonAutonomousProxyOnly: true`, `usability: null`, `liveClaimEligible: false`); only fresh, complete `'verified-live'` evaluations passing all provisional SLOs set `liveClaimEligible: true`.
3. **Date-range, milestone (`M01`–`M05`), and lane filtering with completeness & staleness**: filters validated observations over `[fromMs, toMs)` (`nowMs >= toMs`, positive `maxAgeMs`, boolean `sourceComplete`) and optional `filters` (`repositoryIds`, `milestones` in `['M01', 'M02', 'M03', 'M04', 'M05']`, and bounded `lanes` slugs). Explicitly reports `observationCount`, `lastObservedAtMs` (`null` when `observationCount === 0`), `freshnessStatus` (`'fresh'` | `'stale'` when `nowMs - lastObservedAtMs > maxAgeMs` | `'unknown'`), and `dataCompletenessPct` (`(populatedCells * 100) / (observationCount * expectedFieldsPerObservation)` when `observationCount > 0 && sourceComplete`, otherwise `null`—never `0` on empty or unverified inventory).

### Customer One usability & portfolio metric dictionary

| Metric key | Provisional SLO / role | Missing / partial behavior |
| --- | --- | --- |
| `initialPlanMs` | `<= 300_000` ms (`5 min`) | `null` percentiles and `sloStatus: 'unknown'` unless an observed sample exceeds `300_000` (`'failed'`) |
| `basicIntegrationMs` | `<= 900_000` ms (`15 min` after prerequisites) | `null` percentiles and `sloStatus: 'unknown'` unless an observed sample exceeds `900_000` (`'failed'`) |
| `mandatoryUserSettingsCount` | `<= 5` user-supplied settings (excluding explicit authorization/credential entries tracked separately in `explicitCredentialEntryCount`) | `null` bounds and `sloStatus: 'unknown'` unless an observed sample exceeds `5` (`'failed'`) |
| `generatedFilesCount` | Informational onboarding overhead (`total`, `min`, `p50`, `p95`, `max`) | `total: null` whenever `observationCount === 0`, `sourceComplete === false`, or any observation is `null` |
| `manualInterventionsCount` | `=== 0` routine manual interventions | `total: null` and `sloStatus: 'unknown'` on missing/incomplete data; `'failed'` on any observed `> 0` |
| `additionalMandatoryServicesCount` | `=== 0` mandatory extra services/subscriptions | `total: null` and `sloStatus: 'unknown'` on missing/incomplete data; `'failed'` on any observed `> 0` |
| `localSoftwareRequiredCount` | `=== 0` mandatory local software installations | `total: null` and `sloStatus: 'unknown'` on missing/incomplete data; `'failed'` on any observed `> 0` |
| `providerCapacityBlocksCount` | Informational capacity-block counter (`total`, `confirmedTotal`, `p50`, `p95`, `max`) | `total: null` on missing/incomplete data; `confirmedTotal` preserves observed lower bound when `knownCount > 0` |
| `attributableSpendUsdCents` | `=== 0` verified attributable spend (`$0.00`) | Unverified/missing spend (`null`) is never treated as `0`; `'failed'` immediately on any observed `> 0` |
| `lastObservedAtMs` | Latest `observedAtMs` in filtered `[fromMs, toMs)` scope | `null` when `observationCount === 0`; compared against `nowMs - maxAgeMs` for `'fresh'` vs `'stale'` |
| `observationCount` | Distinct deduplicated observations matching `[fromMs, toMs)` and active filters | `0` count with all dependent aggregates/timestamps/percentages kept `null` (`unknown`) |
| `dataCompletenessPct` | Populated metric-cell percentage across in-scope observations (`0..100`) | `null` whenever `observationCount === 0` or `sourceComplete === false` |
