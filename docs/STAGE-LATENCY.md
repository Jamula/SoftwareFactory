# Delivery latency decomposition and hosted execution receipts (#9, #10, #16, #18)

Supports logical milestone **M01.06** ([#9](https://github.com/Jamula/SoftwareFactory/issues/9)) and the **M02.02** scorecard reporting contract ([#18](https://github.com/Jamula/SoftwareFactory/issues/18); historical M04 reference preserved).

## Candidate stage latency (`tools/engineering-factory/stage-latency.mjs`)

Measure one candidate generation from ready push to CI and independent review, eligibility, enrollment, merge receipt, and main verification:

- `stageLatency(e)` evaluates complete synthetic exact-head fixture timelines (`head === observedHead`). Parallel CI and independent review overlap, so critical-path validation is `max(ciDone, reviewDone) - ready` rather than their sum. Post-validation evidence delay, eligible-to-enrollment idle, queue time, eligible-to-merge, main verification, and ready-to-verified remain separate.
- `decomposeCandidateLatency(e)` extends exact-head decomposition to both `'synthetic'` and `'github-hosted'` sources while strictly rejecting `'github-proxy'` / `'historical-proxy'` inputs so historical proxies never mix with autonomous execution outcomes. Open or blocked right-censored candidates report `censored: true` and `null` for unreached stages (never `0`), out-of-order or prerequisite-skipping timestamps fail closed with `'INVALID_ORDER'`, `outlierOver25m` flags completed `readyToVerifiedMs > 1500000` (>25 minutes), and returned records omit commit SHAs.
- `normalizeStageDurations(stages)` validates per-stage millisecond maps (`reconcile`, `normalize`, `evaluate`, `dispatch`, `ci`, `queue`, `review`, `merge-shadow`, `verify-main`, `acceptance`), preserving `null` for unmeasured stages.

## Sanitized execution receipts (`tools/engineering-factory/telemetry.mjs` and `run.mjs`)

GitHub-hosted runs do not require a personal laptop, open chat, or local OTLP collector to record structured execution evidence:

- `telemetrySummary(result)` maps runner, planner, coordinator (`LEASE_HELD`, `LEASE_LOST`, `LEASE_UNAVAILABLE`, `CLOCK_UNAVAILABLE`, `ACTIVE_PATH_CONFLICT`, `DEPENDENCY_UNKNOWN`, `INVALID_PROJECT_CONFIG`, `TASK_READ_FAILED`, `TASK_STATE_CHANGED`, `AGENT_REVIEW_FAILED`), event-journal (`NO_CLAIM`, `SHADOW_RECONCILED`, `SHADOW_HEAD_SUPERSEDED`, `EVIDENCE_UNKNOWN`, `CLAIM_LOST`), and protected-merge (`SHADOW_SQUASH_ELIGIBLE`, `SHADOW_MAIN_VERIFIED`, `PROTECTIONS_UNVERIFIED`, `REVIEW_UNVERIFIED`, `COVERAGE_UNVERIFIED`, `CHECKS_INCOMPLETE`, `STALE_HEAD_OR_BASE`) outcomes to bounded low-cardinality OpenTelemetry attributes (`outcome` in `eligible|blocked|failed|unknown`; `reason` in `NONE|INVALID_EVIDENCE|STALE|DEPENDENCY|QUOTA|POLICY|SECURITY|LEASE|REVIEW|COVERAGE|CHECKS|RUNTIME|OTHER`). Unrecognized strings collapse to `'OTHER'` without leaking raw messages.
- `createExecutionReceipt(input)` produces a versioned, fail-closed receipt (`schemaVersion: 1`, `valid`, `shadow: true`, `liveDispatch: false`, `liveMerge: false`, `source`, `repositoryId`, `receiptId`, `observedMs`, `stage`, `outcome`, `reason`, `durationMs`, `stages`, `quota`, `cost`, `humanTouches`, `correlation`). Unverified quota, cost, and human-touch evidence remain `'unknown'` with `null` values; verified zero incremental spend is recorded explicitly as `{ state: 'verified-zero', verified: true, currency: 'USD', amountMicros: 0 }`. Inputs containing unexpected fields, prompts, tokens, identities, proxies, accessors, or live-mutation flags fail closed.
- `receiptStageRows(receipt)` projects validated receipts into stage rows (`reconcile`, `dispatch`, `ci`, `review`, `merge`, `verify-main`, `acceptance`) while preserving exact `source` (`'synthetic'` or `'github-hosted'`). `'synthetic'` rows feed `stage-aggregate.mjs` directly today; hosted provenance scorecard aggregation is owned by `#18` (`tools/engineering-factory/stage-aggregate.mjs`).
- `node tools/engineering-factory/run.mjs [--smoke|--inventory|--reconcile-pull|--reconcile-issue] [--receipt]` preserves all existing flags, stdout payloads, and exit codes when `--receipt` is omitted, requires `RUNNER_ENVIRONMENT === 'github-hosted'` alongside `GITHUB_ACTIONS === 'true'` and verified repository/run metadata before labeling provenance `'github-hosted'`, and emits sanitized execution receipts with distinct per-execution local IDs (or an injected `receiptId` in `run()`) when `--receipt` or `writeReceipt` is supplied.

Preserve existing `<=120s` eligible batch target, `>=98%` line and `>=95%` branch coverage per executable component and overall, exact-head independent review, and `$0` incremental spend. No deployment, remote exporter, credentials, or live mutation is enabled here.
