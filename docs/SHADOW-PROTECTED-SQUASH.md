# Protected squash simulation

`tools/engineering-factory/protected-squash.mjs` exercises SoftwareFactory's protected squash path using synthetic evidence. It has no GitHub client. Every result keeps `liveMerge` false. A native queue requirement stops this path, including when the adapter cannot establish whether the queue is required.

An intent names the repository, immutable repository ID, `main`, PR number, candidate head, and expected base. The controller serializes on one instance and reads fresh candidate evidence before handing the same frozen identifiers to the simulated operation. The injected reader must independently verify repository policy, effective rules and legacy protections, authority, review history and findings, required checks and producers, security, and coverage inventory. The factory evaluator, platform gate, and per-component coverage receipt must all pass for the exact head. A stricter repository coverage policy still applies. A changed base, stale or adverse review, wrong producer, missing evidence, failed main, or stopped candidate prevents simulation.

An ambiguous outcome holds the controller. Recovery reads a receipt for the same candidate without making another simulated request. The receipt must bind the expected head and base to a different resulting commit. Dependent work stays blocked until an independent read reports that commit as healthy on `main` and the stop control is clear. The next intent must use that verified base. A changed or rolled-back main stays blocked for operator reconciliation. Nothing automatically rolls back, clears an uncertain receipt, or approves a GitHub operation.

Run the synthetic tests with `node --test tests/engineering-factory/protected-squash.test.mjs`. The caller needs bounded reads and a single controller instance. Durable cross-process ownership and receipt recovery, actual GitHub protection evidence, authorization, and measured eligible-to-merge latency remain open in #8.
