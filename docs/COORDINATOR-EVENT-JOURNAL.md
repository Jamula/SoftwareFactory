# Durable shadow event journal

The local SQLite event journal retains sanitized reconciliation hints across restarts. It stores a configured repository ID, a delivery ID, an event kind, a numeric subject and an observed head. For a repository-wide hint, use subject zero. A delivery replay with the same metadata returns a duplicate receipt. Conflicting metadata with the same repository and delivery ID is rejected. Insertion order determines which hint gets work first.

Use the journal only behind a trusted event adapter, with an owner-controlled local database path. An event is a request to fetch fresh metadata. The stored head never authorizes a decision. After a successful fresh read and reconciliation, the runtime may acknowledge the claim. It must leave unsuccessful attempts unacknowledged for recovery.

A claim is atomic and exclusive per repository. Other repositories can continue concurrently. An expired claim can be recovered with a new generation. Use a consistent trusted clock across local workers. Acknowledgement requires the current owner, generation, and unexpired lease. A successful acknowledgement leaves a receipt for duplicate detection. At 10,000 deliveries for a repository the journal rejects new entries and keeps prior receipts. Retention and rotation need a policy before sustained use.

This API is shadow-only (`liveDispatch: false`, `liveMerge: false`). Ephemeral GitHub Actions runner disks are not authoritative cross-run lease stores on their own; hosted cross-run queue and lease fencing uses `gh-aw` `tools.work-queue` non-force git-ref Compare-and-Swap (`CAS`) on ruleset-protected `refs/heads/work-queue` (`tools/engineering-coordinator/work-queue-cas.mjs`), while live hosted branch/run provisioning and verification remain gated on [#6](https://github.com/Jamula/SoftwareFactory/issues/6).

## Deterministic cross-run snapshots (`exportJournalSnapshot` / `importJournalSnapshot`)

`exportJournalSnapshot(journal, {repositoryId})` exports an insertion-ordered, frozen `schemaVersion: 1` snapshot of sanitized journal entries (`repositoryId`, `deliveryId`, `kind`, `subject`, `head`, `owner`, `generation`, `expires`, `completed`, `retryAfter`, with `retryAfter` always cleared to `null` once `completed` is `true`). Optional `repositoryId` scoping exports only one repository's entries while rejecting malformed scope objects, non-positive IDs, getters, and proxies. Because journal capacity is bounded at 10,000 entries per repository and snapshot imports accept at most 10,000 entries, unscoped exports exceeding 10,000 rows fail closed with `SNAPSHOT_LIMIT`; multi-repository hosts must export per-repository snapshots.

`importJournalSnapshot(journal, snapshot, {now = 0})` validates the entire snapshot and clock atomically before applying `BEGIN IMMEDIATE ... COMMIT`:
- Rejects proxies, accessors, invalid clocks (`CLOCK_UNKNOWN`), sparse or >10,000-entry arrays, unknown fields, duplicate `(repositoryId, deliveryId)` pairs inside the snapshot, unclaimed entries with owners/leases/completion/deferrals, completed entries with active leases or deferrals, imported `expires` or `retryAfter` horizons exceeding `now + 3,600,000` ms (callers restoring real-clock timestamps must pass the trusted `{now}` sample rather than relying on the `0` default), and entries that would exceed the 10,000-entry per-repository cap (`JOURNAL_FULL`).
- Rejects any incoming entry whose `(kind, subject, head)` conflicts with an existing `(repositoryId, deliveryId)` receipt (`DELIVERY_CONFLICT`), rolling back the transaction with zero partial mutation.
- Enforces repository-wide lease exclusivity against the trusted `now` clock (`LEASE_CONFLICT` rollback whenever more than one uncompleted entry in a repository holds `expires > now`, including newly imported or generation-advanced claims) and clears `expires = 0` on expired uncompleted leases when an active lease is present in the same repository.
- Preserves monotonic fencing and completion when replaying into a populated journal: completed receipts never reopen, higher generations advance lower uncompleted claims without regressing newer generations, and `retryAfter` merges monotonically.

## Scoped fresh-read reconciliation (`reconcileJournalOnce` and `reconcileEventTrigger`)

The `reconcileJournalOnce` shadow helper consumes one claim at a time, reads normalized fresh metadata, checks lease time and repository/kind/subject, and completes only the current fenced claim. A freshly observed moved head supersedes the old hint (`SHADOW_HEAD_SUPERSEDED`) without granting any action. Failed or unknown evidence leaves the claim unacknowledged (or durably deferred via `deferUnknown`) for recovery.

`createScopedJournalReader` and `reconcileEventTrigger` in `tools/engineering-factory/event-envelope.mjs` connect trusted GitHub event normalization (`pull`, `issue`, `manual`, `review`, `check`, and `main`) to `event-journal.mjs` using bounded unauthenticated public GitHub REST reads and optional cross-run snapshot import/export. All outputs remain read-only shadow receipts (`evidenceComplete: false`, `liveDispatch: false`, `liveMerge: false`).

## `gh-aw` `tools.work-queue` git-ref CAS vs. runner-local SQLite diagnostics

Customer One and [#6](https://github.com/Jamula/SoftwareFactory/issues/6) require comparing the smallest `$0` GitHub-hosted claim/ledger primitive against runner-local `node:sqlite` stores before adding external infrastructure:

| Capability | `gh-aw` `tools.work-queue` git-ref CAS (`work-queue-cas.mjs`) | Runner-local SQLite diagnostics (`event-journal.mjs`, `sqlite-state-store.mjs`, `shadow-dispatch-ledger.mjs`) |
| --- | --- | --- |
| **Authoritative backing store & cost** | Git commit/blob state and 40-hex OID on ruleset-protected `refs/heads/work-queue` in the GitHub repository (`$0` incremental spend, no external database or always-on daemon). | Runner-local `node:sqlite` file or `:memory:` (`BEGIN IMMEDIATE` transactions). Zero cost locally, but ephemeral GitHub Actions runner filesystems reset between workflow runs. |
| **Cross-run atomic contention** | Concurrent isolated runners read `expectedOid` from `refs/heads/work-queue` and commit strictly via non-force `compareAndSwapRef` (`force: false`; `force: true` fails closed with `FORCE_UPDATE_FORBIDDEN`, other refs fail with `UNPROTECTED_WORK_QUEUE_REF`). Losing writers receive `CAS_CONFLICT`, re-read the updated ref state, and serialize non-overlapping lane claims or abort (`DUPLICATE_ACTIVE_CLAIM`, `LANE_RESERVED`, `OWNED_PATHS_OVERLAP`, `CAPACITY_FULL`). | Atomic only across processes sharing the same local SQLite file. Exported snapshots (`exportJournalSnapshot` / `exportSnapshot`) detect regressions inside a loaded store (`STALE_SNAPSHOT_SEQUENCE`); cross-run reservation fencing requires binding signed `shadow-dispatch-ledger.mjs` snapshots to `refs/heads/work-queue` via `reconcileLedgerWithWorkQueueCas`. |
| **Bounded execution TTL & `generation` fencing** | Enforces `1..3,600,000 ms` (`MAX_LEASE_TTL_MS`) on `leaseTtlMs` and immutable `executionDeadlineMs = claimedAtMs + maxExecutionMs`, clamps renewals (`EXECUTION_TTL_EXCEEDED`), atomically fences expired leases (`nextGeneration++`), and rejects superseded workers with `STALE_GENERATION` alongside `coordinator.mjs`'s bounded execution deadline (`#116` remediation). | `event-journal.mjs` fences per-delivery `generation` and bounds imported horizons to `now + 3,600,000 ms`; `sqlite-state-store.mjs` fences paired lane + `repo#issue` active claims per tick without a durable terminal completion ledger; `shadow-dispatch-ledger.mjs` bounds local reservation/in-flight deadlines and fences cross-run CAS generations (`STALE_LEASE_GENERATION`, `LEASE_TTL_EXCEEDED`). |
| **Authoritative work identity & event replay** | Keyed directly to GitHub work items (`${repositoryId}:issue:${issueNumber}` and `${repositoryId}:pr:${pullNumber}:${headSha}` — no second backlog), durably deduplicating `workId` (`DUPLICATE_ACTIVE_CLAIM`, `WORK_ALREADY_COMPLETED`, `WORK_CANCELLED`, `RETRY_CEILING_EXHAUSTED`) and every consumed `(runId, runAttempt)` tuple across the entry's retry lifetime via `priorRuns` (`DUPLICATE_RUN_ATTEMPT`) across `entries` (`250`) and non-evicting `archivedTerminal` (`2,000`, failing closed with `ARCHIVE_CAPACITY_EXHAUSTED`); runner-local pre-CAS ingestion (`replay_events`) additionally guards `(repositoryId, deliveryId)` (`DUPLICATE_DELIVERY`, `DELIVERY_CONFLICT`), `eventSequence` (`OUT_OF_ORDER_EVENT`), and fresh PR head reads (`STALE_HEAD_SUPERSEDED`). | `event-journal.mjs` deduplicates `(repositoryId, deliveryId)` webhook hints up to `10,000` deliveries per repository and treats stored heads strictly as fresh-read hints (`SHADOW_HEAD_SUPERSEDED`). |
| **Crash recovery & emergency `stop`** | `reconcileWorkQueueRunStates` recovers `launch_failed`, `worker_terminated`, `run_terminal` (with verified `conclusion` prior to `leaseExpiresAtMs`), `run_missing`, and `lease_expired` into sanitized `recoveryReceipts`, and honors emergency `stop` (`STOPPED`) without mutating committed ref state. | Unacknowledged claims recover locally once `expires <= now` or `retryAfter <= now` for single-host Aspire and diagnostic shadow polling (`LOCAL-SHADOW-HOST.md`). |

### Operating boundary and lifecycle verification

- **Primary hosted queue/lease primitive:** `work-queue-cas.mjs` (`planUnifiedWorkQueue`, `claimWorkQueueLease`, `renewWorkQueueLease`, `settleWorkQueueLease`, `reconcileWorkQueueRunStates`, and `simulateDurableCasLifecycle`) pairs `github/gh-aw` `tools.work-queue` git-ref CAS (`protocol: v3` under pinned `v1.2.2`, with `v4` gated on verified compiler pin upgrades) with SoftwareFactory's deterministic `planner.mjs` non-overlapping file-set/lane moat and bounded execution TTL.
- **Role of runner-local SQLite modules:** Retained as zero-network local diagnostic, Aspire telemetry, and single-host shadow reconciliation stores; they are not treated as authoritative cross-run hosted lease stores, and overlapping custom state is retired only after equivalent live hosted evidence is accepted.
- **Escalation policy:** **Cloudflare Durable Objects (Free plan)** remains strictly an owner-approved escalation option if git-ref CAS contention ever warrants it; **Temporal and LangGraph are excluded**.
- **End-to-end simulation vs. live hosted gate:** `simulateDurableCasLifecycle(scenario)` deterministically verifies multi-worker non-force CAS contention, cold-boot runner restarts from serialized `refs/heads/work-queue` state, `generation`-fenced stale worker rejection, `(repositoryId, issueNumber)` and `(repositoryId, pullNumber, headSha)` out-of-order/duplicate event replay idempotency, crash recovery (`launch_failed`, `worker_terminated`, `run_terminal`, `run_missing`, `lease_expired`), ready-to-claim latency/occupied duration metrics, and immediate `stop` preservation (`shadow: true`, `liveDispatch: false`, `liveMerge: false`). Live GitHub-hosted `refs/heads/work-queue` branch/ruleset provisioning and workflow-run execution remain open acceptance items on [#6](https://github.com/Jamula/SoftwareFactory/issues/6).

## Cross-run `shadow-dispatch-ledger.mjs` ↔ `work-queue-cas.mjs` reservation fencing

`verifySignedLedgerSnapshot`, `computeWorkQueueStateOid`, `computeReservationHeadLock`, and `reconcileLedgerWithWorkQueueCas` in `tools/engineering-factory/shadow-dispatch-ledger.mjs` bind signed runner-local dispatch ledger snapshots directly to `refs/heads/work-queue` CAS state and [#7](https://github.com/Jamula/SoftwareFactory/issues/7) / `#105`'s `$0` overage hard-stop contract without performing network, filesystem, or Git mutations (`shadow: true`, `liveDispatch: false`, `liveMerge: false`):

1. **Signed ledger snapshot integrity (`verifySignedLedgerSnapshot`):**
   - Rejects `null`, `Proxy` (including revoked proxies), non-`Object.prototype` records, non-dense arrays, accessors, and unknown fields before evaluating data.
   - Verifies both `SHA-256` `digest` and `HMAC-SHA256` `hmac` via `timingSafeEqual` over `[version, planSignature, sequence, exportedAt, reservations]` (`SNAPSHOT_SIGNATURE_INVALID` on unsigned tampering), validates canonical `planSignature` bounds (`PLAN_SIGNATURE_MISMATCH` when mismatched against `fixturePlan`), enforces `minSnapshotSequence` (`STALE_SNAPSHOT_SEQUENCE`) and `maxSnapshotAgeMs` (`STALE_LEDGER_SNAPSHOT`), and verifies sorted row order, unit totals, and per-repo/global active limits.
2. **Protocol `v3` baseline vs. gated Protocol `v4`:**
   - Pinned `github/gh-aw` `v1.2.2` (`work-queue-cas.mjs`) emits and consumes `protocol: 'v3'` as the verified baseline.
   - `protocol: 'v4'` (or `requestedProtocol: 'v4'` on an empty queue) is admitted **only** when `protocolV4ReleaseVerified === true` (at top-level or in `admissionEvidence`, with conflicting boolean flags rejected); otherwise reconciliation fails closed with `UNVERIFIED_QUEUE_PROTOCOL`. Any other protocol string also fails closed with `UNVERIFIED_QUEUE_PROTOCOL`.
3. **`#105` `$0` paid-overage hard-stop & native GitHub Cloud Agent contract (`admissionEvidence`):**
   - Requires `personalPatConfigured === false` (`PERSONAL_PAT_FORBIDDEN`), `includedOnly === true` (`INCLUDED_ONLY_REQUIRED`), affirmative `overageDisabled === true` and `hardStopEnforced === true` (`OVERAGE_HARD_STOP_REQUIRED`), `incrementalSpendUsdCents === 0` (`NONZERO_INCREMENTAL_SPEND`), affirmative `authorityVerified === true` and `entitlementVerified === true` (`BILLING_AUTHORITY_UNVERIFIED`), mandatory matched positive `(repositoryId, approvedRepositoryId)` matching any candidate (`REPOSITORY_SCOPE_MISMATCH`), fresh `observedMs` within `maxQuotaAgeMs` (`STALE_ADMISSION_EVIDENCE`), and explicit `remainingIncludedUnits` (`BUDGET_UNKNOWN` when omitted or out of bounds).
   - Enforces valid execution harnesses: `'copilot-cloud-agent'` on `'public'`, `'private'`, or `'internal'` repositories (requiring `agentLogin === 'copilot-swe-agent[bot]'` when specified, `AGENT_IDENTITY_MISMATCH` otherwise); `'copilot-cloud-automation'` **only** when `repositoryVisibility === 'private' || repositoryVisibility === 'internal'`, failing closed with `AUTOMATION_REQUIRES_PRIVATE_REPO` on `'public'`; and `'copilot-sdk'` only with pinned `sdkVersion` `'2.0.3'` (`SDK_VERSION_MISMATCH` otherwise). Optional `gh-aw` soft caps (`ghAwCaps`: `maxAiCredits`, `maxDailyAiCredits`, `dailyAiCreditsUsed`, `runAiCreditsRequired`) fail closed on invalid or exceeded run/daily credit budgets during both new reservation and `reserved -> in-flight` startup (`GH_AW_SOFT_CAPS_INVALID`, `GH_AW_MAX_AI_CREDITS_EXCEEDED`, `GH_AW_DAILY_AI_CREDITS_EXCEEDED`).
4. **Deterministic CAS fencing, TTL reclamation (`<= 3,600,000 ms`), owner/head binding, complete cross-run quota accounting, and orphan release:**
   - Enforces `targetRef === 'refs/heads/work-queue'` (`UNPROTECTED_WORK_QUEUE_REF`), `force !== true` (`FORCE_UPDATE_FORBIDDEN`), and exact 40-hex `expectedRefOid` match against the observed/computed `casState` OID (`CAS_CONFLICT` with `{expectedRefOid, actualRefOid}` on mismatch).
   - Rejects CAS entries or candidates with `leaseTtlMs > 3,600,000` or `maxExecutionMs > 3,600,000` (`LEASE_TTL_EXCEEDED`), rejects backward clock skew (`CLOCK_SKEW_REJECTED`), and rejects stale or out-of-order lease generations across ledger rows, CAS entries, and recovery receipts (`STALE_LEASE_GENERATION`).
   - Requires explicit `(workerId, runId, runAttempt)` ownership (`LEASE_OWNER_MISMATCH`) and SHA-256 head-plus-checkpoint binding (`computeReservationHeadLock` `'00...'` pre-bind lock upgraded to `'c1...'` reserved and `'c2...'` started/in-flight locks carrying the signed `nextLedgerSnapshot.digest` tag in `lockSha256`; `HEAD_BINDING_MISMATCH` on head or unlocked issue mismatch, `STALE_OR_INCOMPLETE_LEDGER` on pre-start or stale-digest replay) when binding or advancing an active CAS lease, while advancing `casState.sequence` (`casMutationRequired: true`) on every candidate reservation or start so concurrent bindings contend on `refs/heads/work-queue`.
   - Audits `ledgerSnapshot` completeness against `casState.entries` (`attempts` / `priorRuns`), strict 2-key `{workId, status}` `archivedTerminal` items (`work-queue-cas.mjs` compatible) paired with cumulative 16-bit archived attempt/charge totals persisted inside checkpoint `lockSha256` fields, and `recoveryReceipts` (failing closed on receipt-buffer saturation when external archives lack surviving checkpoint locks) (`STALE_OR_INCOMPLETE_LEDGER`). Attributes PR compaction and audit charges per exact `(repositoryId, pullNumber, headSha)` rather than across distinct PR heads, releases unstarted `'reserved -> cancelled'` expiry capacity without charging `authoritativeSpentUnits`, separates cumulative `plan.includedUnits` window accounting from live `remainingIncludedUnits` (honoring optional `netOfReservationsVerified`), sums each peer reservation's persisted 8-hex AI-credit commitment in `ghAwCaps` projections (`PEER_CREDIT_COMMITMENTS_UNKNOWN`, `GH_AW_DAILY_AI_CREDITS_EXCEEDED`) without double-counting `dailyUsageIncludesReservations: true` startups, bounds `in-flight` ledger `validThrough` by immutable `executionDeadlineMs` rather than renewable `leaseExpiresAtMs`, rejects duplicate numeric subjects across both `issue` and `pull_request` targets (`ACTIVE_CAS_LEASE_CONFLICT`, `DUPLICATE_RESERVATION`), and allows passive expiry/orphan cleanup mutations even when `remainingIncludedUnits === 0` while blocking new reservations and `in-flight` starts (`CAPACITY_EXHAUSTED`).
   - Reclaims expired CAS leases (`leased -> requeued | exhausted` with incremented `nextGeneration`) and expired ledger rows (`reserved -> cancelled`, `in-flight -> expired`), releases orphan ledger reservations left behind by terminal/crashed/missing runs (`observedRuns`), compacted `archivedTerminal` items, superseded generations, or unbacked local reservations, and blocks duplicate `(repositoryId, issue, head)` or active `(repositoryId, issue)` reservations (`DUPLICATE_RESERVATION`) as well as cross-runner repo/global slot saturation (`REPO_CAPACITY_EXHAUSTED`, `CAPACITY_EXHAUSTED`).

### `refs/heads/work-queue` repository ruleset specification

Before enabling live hosted workflow-run persistence under [#6](https://github.com/Jamula/SoftwareFactory/issues/6) and [#7](https://github.com/Jamula/SoftwareFactory/issues/7) (separately owner-gated), the repository must enforce a dedicated GitHub branch ruleset targeting exact ref `refs/heads/work-queue`:

| Ruleset rule | Required setting | Purpose |
| --- | --- | --- |
| **Target ref** | Exact `refs/heads/work-queue` | Isolates machine-managed CAS queue/lease commits from `refs/heads/main` source history and prevents queue updates from retriggering code CI. |
| **Restrict creations, updates, and deletions** | Scoped orchestrator GitHub App / workflow identity only (zero personal PATs) | Prevents untrusted workflows, pull requests, or personal credentials from forging queue leases or clearing terminal receipts. |
| **Block force pushes (`non_fast_forward`)** | Enabled | Guarantees Git-level atomic fast-forward / expected-OID CAS semantics matching software `force: false` (`FORCE_UPDATE_FORBIDDEN`). |
| **Block deletions (`deletion`)** | Enabled | Preserves monotonic `sequence`, `nextGeneration`, `priorRuns`, and `archivedTerminal` deduplication history across runs. |
| **Require linear history (`required_linear_history`)** | Enabled | Ensures every accepted CAS state transition is a single-parent commit over the prior 40-hex `expectedRefOid`. |
| **PR / code status-check exemptions** | Exempt on `refs/heads/work-queue` only (`refs/heads/main` stays fully protected) | Allows sub-second atomic `git/refs/heads/work-queue` CAS commits without human PR gates while keeping `refs/heads/main` behind independent review, CI, and CodeQL. |
