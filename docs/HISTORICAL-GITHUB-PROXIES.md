This read-only report provides the historical proxy part of #9 and an input for #18. It uses public repository metadata and runs offline after collection.

Use the [committed evidence snapshot](evidence/softwarefactory-github-proxies-2026-11-25.json) to reproduce this table. It records the sanitized rows, exact query, repository allowlist and source page counts at acquisition. The GitHub URLs will show newer data when fetched again. A one-sample percentile is the same observation.

Censored includes items still open in the source and items with an end at or after the cutoff. The issue proxy uses the close timestamp visible in the snapshot. It does not reconstruct earlier closures or reopened transitions. Draft and review waiting is part of the PR proxy. An issue close or PR merge does not establish readiness, accepted work, main health, causal issue linkage, cost, or an SLO result. See [the separate CI baseline](VALIDATION-TIMING-BASELINE.md) and [the metric contract](ENGINEERING-METRIC-CONTRACT.md).

## Reproduce or consume the report

From the repository root, replay the frozen snapshot offline. The resulting p50 and p95 values are in milliseconds.

```shell
node --input-type=module -e "import {readFileSync} from 'node:fs'; import {aggregateGithubTiming} from './tools/engineering-factory/stage-aggregate.mjs'; const {rows, query, authorizedRepositoryIds} = JSON.parse(readFileSync('docs/evidence/softwarefactory-github-proxies-2026-11-25.json','utf8')); for (const [metric, samples] of Object.entries(rows)) console.log(JSON.stringify(aggregateGithubTiming(samples, {...query, metric}, authorizedRepositoryIds)));"
```

For a new report:

1. Fetch the relevant authorized repository's public PR and issue metadata without retaining bodies, titles, or actor fields. Follow pagination to the end of the relevant cohort. If source coverage cannot be established, set `sourceComplete: false`. Discard rows with `pull_request` from the issue dataset.
2. For each metric retain only `id` (issue or PR number), `repositoryId`, `metric`, `openedMs`, `endedMs`, and `state`. Use integer UTC epoch milliseconds. For `pr-created-to-merge` use the merge timestamp and `completed`, or the close timestamp and `closed-unmerged`. For `issue-created-to-close` use the visible close timestamp and `completed`. Leave the end null for `open` or `unknown`. Represent unavailable terminal timestamps with `unknown`. Do not combine metrics or repositories in a call.
3. Call `aggregateGithubTiming(rows, query, authorizedRepositoryIds)` from `tools/engineering-factory/stage-aggregate.mjs`. The trusted caller supplies the repository allowlist and a query with `repositoryId`, `metric`, `fromMs`, `toMs`, `observedMs`, `nowMs`, `maxAgeMs` and `sourceComplete`. The acquisition must be at or after the cohort cutoff. For a frozen historical report, record the generation time and provenance. For a live view, pass the real current time and refuse stale snapshots.
4. The response uses nearest-rank percentiles in milliseconds, based on completed samples only. It retains cohort, censored, closed-unmerged and unknown counts. Identical rows are deduplicated. Contradictory rows fail the entire query. Partial source coverage or unknown rows are flagged separately from exact measurements. Without a completed sample, p50 and p95 are null.

This interface does not collect data, launch a UI, or schedule a report. GitHub does not supply a consistent cross-repository cohort or verified acceptance in these list endpoints. A later report must bind those claims to authorized evidence. The historical proxy snapshot is separate from the synthetic stage metrics and does not close #9 or #18.

## T01–T04 historical proxy and autonomous OTel report contract (`#9`)

`buildHistoricalAndOtelEvidenceReport(input)` in `tools/engineering-factory/historical-baseline-report.mjs` implements `#9`'s `T01–T04` repeatable read-only reporting boundary (`HISTORICAL_OTEL_REPORT_SCHEMA_VERSION = 1`, `shadow: true`, `readOnly: true`, `liveDispatch: false`, `liveMerge: false`, `createsSchedule: false`, `reportingCadence: 'existing-scorecard-cadence'`). Every input record is validated fail-closed via `types.isProxy` and plain-object own-enumerable-data-descriptor checks before reading properties, rejecting proxies, getters, custom prototypes, symbols, and unsanitized private fields (`title`, `body`, `author`, prompts, tokens).

### Provenance quarantine: historical proxies vs autonomous OTel outcomes

Historical GitHub timestamp proxies (`provenance: 'historical-github-proxy'`, `nonAutonomousProxyOnly: true`, `sloEligible: false`) and verified autonomous OpenTelemetry outcomes (`provenance: 'verified-autonomous-otel' | 'synthetic-otel-fixture'`) are strictly isolated and never blended:

### T01–T04 slice guarantees

1. **Per-repository cohort authorization (`T01`, `T03`)**: `query.repositoryKey` is restricted to `SUPPORTED_COHORT_REPOSITORIES` (`SoftwareFactory` bound to repository ID `1471342715`, `FamilyTree`, `Spellbook`, `FamilyHub`) and must match an entry in `authorizedRepositories` with `readAuthorized: true`. Repository names never grant authorization. Any record from another `repositoryId` fails closed with `CROSS_REPOSITORY_CONTAMINATION`; mismatched cohort slugs fail closed with `COHORT_MISMATCH`; stale snapshots (`nowMs - observedMs > maxAgeMs`) fail closed with `STALE_EVIDENCE`.
2. **Explicit correlation, partial/reopened work, censored open work, and `null` missing timestamps (`T02`)**:
   - **Linkage provenance**: only explicit `ALLOWED_EXPLICIT_LINK_KINDS` (`closing-keyword`, `timeline-cross-reference`, `verified-receipt-binding`) establish issue-PR attribution. Heuristic `title-similarity` links are quarantined under `correlation.rejectedTitleSimilarityLinks` and never establish `issueCreatedToFirstPrMs`, `issueReadyToFirstPrMs`, or `issueReadyToOutcomeMs`.
   - **Many-to-many & unlinked PRs**: supports `1-to-many` (`multiPrIssueNumbers`) and `many-to-1` (`multiIssuePullNumbers`) graphs, deduplicates identical explicit links, fails closed on conflicting `partial` link flags (`CONFLICTING_LINK_EVIDENCE`), and surfaces unlinked PRs in `unlinkedPullNumbers`.
   - **Partial PRs & reopened issues**: issues backed only by `partial: true` PRs classify as `partial-only` and never count as accepted outcomes even if prematurely closed. Issues reopened at or after `acceptedAt` classify as `reopened-unaccepted`; issues reopened after `readyAt` and later re-verified preserve the original `readyAt` without resetting the clock.
   - **Censoring & missing timestamps**: items still open at `observedMs` or completing at/after `toMs` are right-censored (`censored` + `overdueOpenCount`) and excluded from completed duration percentiles. Missing or chronologically invalid timestamps always produce `null` and increment `unknown` counts—never `0`.
3. **Repeatable throughput & checkpoint comparison (`T03`)**: counts verified accepted outcomes once per issue (`acceptedOutcomesInWindow`, `otelVerifiedAcceptedOutcomesInWindow`, `acceptedOutcomesPerDay`), records `mergedPullsInWindow` with `mergedPullsActivityOnly: true`, reuses the existing scorecard cadence (`createsSchedule: false`), validates baseline rate and zero-safety-violation consistency, rejects mixed OTel/non-OTel accepted populations, enforces passed per-component and per-PR exact-head `guardrails` (`expectedComponents`, `mainCoverage` bound to the cohort's latest verified `mainVerifiedSha`, and `pullReceipts` bound to every required PR's candidate `headSha` with `independentReviewVerified: true`, enforcing `>= 98% / 95%` SoftwareFactory and `>= 95% / 90%` consumer floors on every component) with independent non-regression checks across line coverage, branch coverage, `reworkRounds`, `reopenedCount`, and human interventions (`GUARDRAIL_UNVERIFIED_OR_REGRESSED`), and evaluates `THROUGHPUT_CHECKPOINTS` (`2x`, `5x`, `10x`, `15x`, `20x`, `25x`) only across non-overlapping equal-duration windows of the same authorized repository, cohort, and pure OTel provenance with `>= 5` comparable OTel-verified accepted units and verified zero routine human interventions.
4. **Non-blocking OTel & W3C `traceparent` receipt integration (`T04`)**: omitting `otel` (or passing `otel: null`) leaves `autonomousOtel.status === 'not-provided'` without blocking `T01–T03`. When `otel` is supplied, `receipts` are validated against `telemetry.mjs` (`EXECUTION_RECEIPT_SCHEMA_VERSION = 1`, `receiptStageRows`, separating `eligibleStageEventCounts` from diagnostic `stageEventCounts` / `blockedByReason`) and optional W3C `traceparents` bindings are verified via `parseTraceparent`. Pre-window (`< query.fromMs`) stage receipts and completed `ciRuns` are excluded from in-window stage percentiles while remaining available for causal lineage of carryover outcomes accepted inside `[query.fromMs, query.toMs)`. Setting `autonomousClaimEligible: true` requires event-bound, chronologically ordered per-outcome `outcomeBindings` (`issue.readyAt <= dispatch`, `ciRun.completedAt <= ci`, `pull.mainVerifiedAt <= verify-main`, `issue.acceptedAt <= acceptance < query.toMs`, and `dispatch <= ci <= verify-main <= acceptance`) linking each accepted issue to a distinct in-window `eligible` `acceptance` receipt plus `eligible` `dispatch`, `ci`, and `verify-main` receipts and completed `ciRuns` (`pull.createdAt <= candidateEventAt <= startedAt <= completedAt <= pull.mergedAt`) on the pre-merge candidate `pull.headSha` (separate from squash `mergeSha`) sharing the exact `traceId`, 100% verified included quota and `$0` cost, reconciled receipt `humanTouches` (`CONFLICTING_INTERVENTION_EVIDENCE` if verified receipt touches exceed per-issue or cohort interventions), passed per-component/per-PR `guardrails`, pure OTel-verified accepted outcomes, and verified zero routine human interventions.
