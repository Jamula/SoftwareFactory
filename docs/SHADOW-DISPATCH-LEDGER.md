# Shadow dispatch reservations

The SQLite ledger and companion quota/scaling evaluators exercise reservation, bounded worker execution deadlines, cross-run snapshot fencing, and `1→2→4→8→10→12` capacity gating for M01.07 ([#7](https://github.com/Jamula/SoftwareFactory/issues/7)) and historical M02.08. They have no provider client. Every result sets `liveDispatch` to `false`.

Open a private local file (or `:memory:` on a stateless runner) with a fixed synthetic capacity plan. The plan binds the included-unit ceiling, units per attempt, total active limit, per-repository limits, bounded worker execution ceiling (`maxExecutionMs`, default 15 minutes, max 60 minutes), and a window identifier. Every process opening the same file or restoring a cross-run snapshot must use the exact same plan signature; pre-deadline `user_version = 0` on-disk ledgers opened with the unchanged default plan are migrated atomically in place to `user_version = 1` so existing spent-unit accounting, duplicate fences, and `expired` phase constraints are preserved (unsupported schema versions fail closed with `SHADOW_DISPATCH_SCHEMA_UNSUPPORTED`). A plan mismatch fails closed. Reservations, expirations, reconciliations, and snapshot transitions execute under `BEGIN IMMEDIATE` transactions, preventing competing connections sharing the same SQLite file from double-claiming the final slot (this atomic claim guarantee applies only within a shared SQLite file, not across separate stateless runners). The same repository, issue, and head stay recorded across lease generations. Another head for the same issue cannot be reserved while an attempt is active. The ledger refuses new records after 10,000 rows.

- **Reserve:** Supply normalized, repository-scoped approval and current lease evidence, plus included-only quota observed within 60 seconds (and optional verified environment and zero-overage `hardStopReceipt` evidence validated against the ledger's authoritative `now`). Expired `reserved` and `in-flight` entries are reclaimed atomically before computing active counts. Unknown quota, enabled overage, unverified environment or hard-stop receipt, a stop, or expired lease denies the reservation.
- **Record a dry run (`begin`):** Supply fresh local lease and stop evidence (observed within five seconds of authoritative `now`) for the same repository, issue, head, and generation, plus an optional per-run `executionTtlMs` no greater than the plan's `maxExecutionMs`. Even if a worker lease is renewed externally, the recorded `in-flight` execution deadline is strictly capped by `Math.min(leaseUntil - 1, now + executionTtlMs)`.
- **Reclaim expired reservations and hung runs (`expire`):** Expired `reserved` entries (`valid_through < now`) transition to `cancelled`, returning both the active slot and unstarted reservation units while keeping the exact `(repository, issue, head)` fenced. Hung `in-flight` runs past their bounded execution deadline transition to `expired`, deterministically releasing repository and global worker capacity while retaining spent units and rejecting late terminal receipts with `EXECUTION_DEADLINE_EXCEEDED`.
- **Cancel before simulation:** Returns the slot and its unstarted units while keeping the exact candidate fenced against duplicate attempts.
- **Reconcile a recorded simulation (`reconcile(ticket, receipt, now)`):** Requires an authoritative `now` timestamp (`now >= reserved_at`) alongside an independently obtained synthetic terminal receipt matching every ticket identifier; omitting `now` or supplying a timestamp earlier than `reserved_at` fails closed (`TERMINAL_RECEIPT_UNKNOWN`). Settling before or at the bounded execution deadline frees the active slot and retains spent units; overdue receipts transition hung `in-flight` entries to `expired` and return `EXECUTION_DEADLINE_EXCEEDED`. Completed, expired, or in-flight attempts are never refunded automatically.
- **Cross-run snapshot export/restore (`exportSnapshot` / `importSnapshot`):** Stateless GitHub-hosted runners export canonical ledger snapshots fenced by the plan signature, monotonic sequence number, SHA-256 payload digest, and HMAC-SHA256 signature (`timingSafeEqual`). Restores verify plan identity, digest/HMAC integrity, exact `unitsPerRun` per row, overflow-safe bounded reservation and execution deadlines (`reservedAt <= exportedAt`, `validThrough - reservedAt <= 60s` for `reserved`/`cancelled`, and `validThrough - min(exportedAt, reservedAt + 60s) <= maxExecutionMs` for `in-flight`/`settled`/`expired`), active/unit invariants, strictly advancing sequence numbers (`STALE_SNAPSHOT_SEQUENCE`), and non-regressing per-ticket lifecycle transitions (`SNAPSHOT_STATE_REGRESSION`). Snapshot signatures and local sequence counters verify payload integrity and non-regression against a loaded target store only; they do not provide authoritative cross-run atomic claims across concurrent fresh in-memory stores or rollback protection without an external atomic fencing store ([#6](https://github.com/Jamula/SoftwareFactory/issues/6)).
- **Hosted `1→2→4→8→10→12` worker ladder (`evaluateHostedWorkerLadder` / `hostedWorkerDispatchIntent` / `verifyHardStopReceipt`):** Enforces single-step worker progression (`verifiedPriorTier` matching the current or immediate predecessor tier, with `0` or `1` permitted at stage `1`) strictly within verified included quota, verified protected environment and worktree isolation, and fresh zero-overage `hardStopReceipt` evidence (`paidUsageMicros === 0`), deriving `actualMaxWorkers` and shortfall (`shortfallMin` / `shortfallMax`) from validated `observedPeak` while reporting prospective ceiling in `verifiedCapacityCeiling` and keeping M01 hosted gates independent of M02 comparative-throughput cohort checks (`recommendShadowScale`).
